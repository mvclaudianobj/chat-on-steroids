## 2.1.52 A list of your scheduled messages, and search through whole long chats

You can now see every scheduled message of your chats in one list, and chat search finds words anywhere in very long chats. Compact & Resume in a Project survives a page reload, and Skills are no longer chosen when you say not to use them.

### 👉 After updating

- Nothing to do. The browser extension updates itself.
- The first chat searches after updating rebuild each chat's search index once, in the background. Results fill in as it goes.

### ✨ New

- **Scheduled.** A new page in the sidebar lists the scheduled messages of all your chats, with when each runs next, how often, and its text. From there you can pause or resume a schedule, run it now, delete it, or open its chat.
- **Search covers the whole history of long chats.** It used to stop after the first million characters of a chat; now every message is searched, however long the chat is, and big chats are read in small pieces so the app stays light.
- **Approve all.** When several tool requests wait for you, one button approves them together after a native confirmation that shows how many there are, how many are flagged suspicious and how many are cut off. Only your click does it: the COO, agents and the API cannot, and a card ChatGPT itself locked stays yours to open.
- **Always allow an exact request.** From a request card you can keep an exact tool, command and folder rule that never asks again. It is listed and revocable in Company settings and never covers publishing, secrets, `sudo` or other folders.
- **Link a chat to a seat or role.** The chat menu has "Link chat to seat & role…" for any chat that is not archived, with a native confirmation before a link is replaced.
- **Task pool check.** A project can ask its COO for a status every 5 or 10 minutes; the app shows the last and next check and why it is waiting. The check also asks the COO to assign idle seats and chase pending reviews, and you can add your own text in `state/project-task-pool-extra.txt`.
- **Import large session databases.** A MarksCode/OpenCode database of any size is read in place instead of copied, sources that were rejected say why, and the list shows size and session count.
- **MarksLLM setup.** A local model through Ollama, off by default, that downloads one named model only after you confirm its origin, licence, size and free space.


### 💪 Better

- **Compact & Resume in a Project after a reload.** If the page reloaded while it ran, it could fail every time afterwards. The app now clears its own leftover brief and goes on.
- **Search retries after a temporary error.** A chat whose search index could not be saved is tried again (at most every 30 seconds) instead of staying out of search until the chat changes.
- **Skills are not chosen when you say not to use them**, and a Skill's name is recognised in Japanese when a particle follows it, as in `code-reviewを使って`.
- **Copied tables keep their own rows** when an answer has several tables with the same column headings.
- **Clearer logs.** A failed schedule action and every decision about a scheduled message (moved, released, timed out) now say which and why, and a Stop that no page took no longer reads as a contradiction.
- **Compact & Resume recovers by itself.** In a Project the replacement chat now opens in its own page in the built-in browser, so the brief reaches it. If that page cannot enter the Project, the app creates one new chat from the saved brief and archives the old chat once it has been idle for three minutes. A proof that the new chat answered survives later messages in it.
- **Backup copes with a busy profile.** Every live file is saved as its own coherent copy, rotating files that vanish during the copy no longer fail the run, and unreadable pieces are never archived half written.
- **The task pool check cannot get stuck.** A check whose answer never arrives is released after 30 minutes and the next one is scheduled; a chat with its browser tab closed can still be the COO.
- **Safer worker requests.** Requests that look destructive, remote-executing, secret-reading, publishing or uploading are held for you and can never be approved by the COO, an agent or the remote API.
- **Control API.** It can name and rename chats, report the selected browser, set model and effort, manage projects and automations, and read notifications, always with a native confirmation for company changes.


### 🛠 Fixed

- A very long chat title or message on the Scheduled page wraps inside its card instead of pushing the page sideways.
- The "Link chat to seat & role" option no longer disappears for chats whose browser tab is closed.
- Session import no longer ignores a database over 8 GiB.
- Dialogs of the approval and MarksLLM flows are translated in all twelve languages.
