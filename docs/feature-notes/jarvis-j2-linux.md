# Jarvis J2 — Linux voice input

Settings > Jarvis offers opt-in push-to-talk for a selected CLIProxy chat on Linux, Windows and macOS. A held F8–F11 key in the composer or held microphone button asks Electron's renderer for an audio-only MediaStream. MediaRecorder buffers chunks in memory up to 12 MB. Releasing ends recording and stops every device track; the bounded audio goes once through a fixed, main-frame-only IPC to the chosen transcriber. Blur, navigation, disabling, losing permission and changing chats discard pending audio, and the process quits with active transcription aborted. Only recognized text is sent to the selected API chat. No audio is persisted by the capture path.

The first choice uses the configured CLIProxy API endpoint's `/models` catalog and the API key already kept by Chat Marks; the app lists audio-transcription candidate IDs without making paid inference calls. An advertised model is not a guarantee `/audio/transcriptions` works. Audio submission uses multipart/form-data to `/v1/audio/transcriptions` with a 45-second deadline, response cap and cancellation. Model discovery errors, permission failures and unsupported recorders display a message in the Jarvis page. A call to `/models` without the configured key may get HTTP 401. The microphone permission and permission to transmit audio to CLIProxy are session-only, and Jarvis starts disabled.

The optional local mode requires **already installed** `ffmpeg`, whisper.cpp `whisper-cli`, and a model. Set `MARKS_JARVIS_WHISPER_CLI` to the absolute binary path and `MARKS_JARVIS_WHISPER_MODEL` to an absolute model path before launching Electron. The engine uses a unique directory under the system temporary folder to decode to mono 16 kHz WAV, runs whisper-cli, reads its UTF-8 text, and removes the entire directory in `finally`. No installer is run. Windows native recognition remains available, and the preferred-engine setting chooses the first available engine in the order displayed.

Live acceptance requires a permissioned microphone, a working audio-capable CLIProxy account/model or installed local whisper.cpp runtime, and a speech utterance. Synthetic validation avoids the user's microphone. The offline generated audio exercise uses `ffmpeg -f lavfi -i sine=frequency=440:duration=1 ...` and validates that a short encoded input can be decoded to 16 kHz WAV. It is **not** evidence that speech is recognized, since a sine tone contains no speech and neither a provisioned local speech model nor authenticated CLIProxy speech inference was available during J2 implementation.
