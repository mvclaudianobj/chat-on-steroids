# Multi Remote — SSH hosts (L)

Open **Settings → Remote hosts** to save an SSH host, including a friendly name, address, port and user. A host profile only stores connection metadata in the Chat Marks user-data directory (`remote-hosts.json`), never a server password. The other profile types (WinRM, PowerShell, WHM and Custom) are listed for future compatibility and are not executable in this version.

To trust an unknown server, inspect the fingerprint displayed by **Trust host fingerprint** and confirm it only after checking it independently. The server's public host key is then appended to the system SSH `known_hosts` file. To install your existing `~/.ssh/marks-key-mestra` identity, select the host, enter its server password in the temporary password input and choose **Install master key on this host**. The password is sent to the local SSH process once and never saved; the server receives only the corresponding public key in `authorized_keys`. The private key remains on this computer. Existing SSH keys are never overwritten or generated automatically.

If the private master key is protected by a passphrase, put that passphrase into **Vault** under the exact name `ssh/marks-key-mestra` using Vault's protected administration workflow, then press **Unlock master key from vault**. The main process supplies the secret directly to `ssh-add`; it is not returned to the renderer or model. The operating system's SSH agent retains the unlocked key for up to one hour. The agent must be configured and running. SSH sessions can also use the existing SSH agent and `~/.ssh/config` settings.

**Open as project** adds an SSH project using the existing project/SFTP implementation (#1469). **Open terminal on this host** creates a project-scoped interactive SSH terminal, with separate terminal tabs when changing hosts. The project implementation and the `remote_exec` tool share SSH key resolution. `remote_exec` requires a verified chat and command permission; a visible approval request shows the host and exact command, with allow once, allow for the rest of that chat's app session, or deny. Its output is bounded and scrubbed by Vault redaction before reaching the chat.

**Preview MarksCode targets** reads a selected copy of `remote-targets.json` as metadata only; secret fields are omitted. **Import preview** publishes the reviewed host list in one atomic catalog write and leaves the source untouched. If the source is inaccessible, copy its JSON content or a readable copy to a location that the file selector can open. The original MarksCode files and databases must remain untouched.

Validation for this feature should include TypeScript checks, the remote hosts and Vault tests, a temporary local `sshd` with freshly generated keys, the full Vitest suite, a production bundle, and a synthetic UI screenshot. Live third-party servers and personal credentials are not required for tests.
