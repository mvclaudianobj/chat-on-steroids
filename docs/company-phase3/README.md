# Pilot real worker broker integration

Company now calls the existing **main-process** `/v1/workers/{ownerId}` implementation directly (no loopback token or renderer worker claim). The **Authorize real worker** action requires an explicit native confirmation. It reserves the selected `marksN` chair in a durable ticket before broker spawn, uses the ticket UUID as the local `ownerId`, then binds returned `runId` and `worker-N` to that chair. Ambiguous failure is not retried: **Check broker progress** inspects the exact owner/run/worker label to reconcile once. This starts real ChatGPT broker workers only in an explicitly configured, non-demo Company with positive token/time budgets. The broker requires Control API actions and multi-agent capabilities to be enabled. Other engine labels remain unsupported by the ChatGPT broker.

Broker refresh accepts only matching worker ID, run ID, ticket label and a report from the owner's broker report inbox; wrong sender, prior reports, missing receipt and active workers cannot be completed. The outcome goes to Review, then **Approve verified completion** requires the human to inspect it and enter review evidence; the main process checks the settled worker against the broker again. Done/rest is not granted by status dragging. The UI and tests provide a conservative safety contract, **not** a hard token/time process kill: the existing broker has no hard budget enforcement for each worker, so the instruction requests restraint and usage is only a guideline. If bounded execution is required, the manager must add broker-side quotas before enabling this pilot for real users.

Meetings persist invites for **all** configured seats. A separate **Send authorized invitations** action asks for native consent, then addresses only bound and currently available workers, storing each queue receipt. Seats without a worker remain invited, never presented as present. **Check verified attendance** consumes only exact broker reports bound to the invitation run/worker and recorded after dispatch, preserving pending/declined/accepted/present and minutes. No periodic polling; each refresh is user-requested. Brain sync is still pending. A worker's language inside a report alone cannot prove human identity or completion; broker envelope identity and session fencing decide.

E2E fixture in `test/company-broker.test.ts` uses a fake worker broker and isolated temporary Company storage. It is not evidence of a live ChatGPT session. Real login, website and worktree data were neither loaded nor modified.
