# Company phase 2 pilot contract

Phase 2 remains an **isolated pilot**, not a live worker orchestrator. The Company UI now exposes a meeting invitation form and a meeting-room details/minutes dialog. Every configured employee seat gets an invitation with explicit `invited` state. No worker is shown as present just because it was invited; confirmed presence requires an independent broker acknowledgement. Since the current worker broker cannot attest `marksN` seat identity in its reports, company IPC **refuses** attendance, worker authorization, and report acceptance rather than inferring them from browser events.

New Company configurations allow 1–10 seats. The schema can still read legacy configurations of 11–99 seats and their existing tickets, and shrink requests fail if they would orphan a ticket. Existing data are neither removed nor migrated destructively. Roles `marks-coo` through `marks-cco` remain fixed.

The main-owned Company store has an operational contract for authorization/receipt phases with exact ownerId + runId + workerId, strict seat ownership, one report per execution, and review before Done. Direct board dragging cannot mark Working or Done without a verified report. A **simulated** store-level end-to-end test admits an explicit binding, rejects wrong-worker receipts and silent seat replacement, records the expected completion evidence, advances to Review, and then closes after review. No real agent was spawned or messaged by these tests.

The Local Control API offers `POST /v1/workers/{ownerId}/spawn`, `POST .../message`, `GET .../reports`, `POST .../ack` plus the independently authorized `POST /v1/inputs` outbox. It identifies actual agents as `worker-N` under `{ownerId, runId}`, not persistent `marksN`; `POST /v1/inputs` returns admission, not proof of delivery. The remaining integration is a main-process bridge that binds these identities durably, verifies broker reports and seat-level acknowledgements, avoids duplicate dispatch, enforces real budgets/permissions, and mirrors actual progress only after recorded ownership proof. The meeting minutes stay local and `brainSync='pending'`; no Brain or notification action is silently performed.

Screenshots contain synthetic records captured by `node scripts/verify-ui.mjs company` in real isolated Electron; these are UI previews and do not evidence live workers.
