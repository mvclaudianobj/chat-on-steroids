# Company O5: broker observation, replay journal and optional RPG

The Office, Board/Kanban and CEO desk remain the default professional UI. An optional third RPG tab is a new CSS-only layout (original art-free geometry), stored locally as `company:view` and driven by the exact Company read-model. The worker is placed at desks only on an observed `active` worker; meeting room only on persisted presence with a confirmed record, rest only after verified COO receipt and no pending work, CEO area on a `needs-ceo` ticket; all unknown/rejected/expired workers stay in the unverified zone. CSS respects `prefers-reduced-motion`. Clicking a seat opens a redacted inspector and timeline. The demo never writes broker observation events.

`src/main/company-observability.ts` reads the existing internal owner-bound `serveWorkerRead` path via `CompanyWorkerBackend.status`, without calling spawn/send/ack/report. Each observed worker must match seat plus exact ticket UUID, ownerId, runId and workerId. States remain conservative when broker evidence is missing, ambiguous or expires (90-second TTL). In particular, unknown session, shell command, account identifiers, exact usage and external Codex/Claude sessions cannot be inferred from this broker and are never portrayed as current Company workers. Shell-wait is reserved in the state contract but has no authoritative source in the current API. Meeting invitation or response without required confirmation is never shown as presence.

Journal: local `company/observations.json` stores only seat, ticket/run/worker UUIDs, operational enum, source and timestamp (no prompts, commands, session contents, account names, credentials or worker result). Atomic write and strict schema; default retention 7 days configurable to 1..30 by a main-only function, max 2000 events. Replay on restart reconstructs the scrubbed timeline, not live liveness. On explicit refresh, a new broker observation is required; unknown/stale status becomes disconnected. No SSE, cloud runtime, external observer, periodic polling, automatically triggered worker, or Habblaud code/assets are included. Inspiration: Habblaud by Marcio Junior (MIT), independently implemented; license https://github.com/marmottajr/habblaud/blob/main/LICENSE.

`test/company-observability.test.ts` tests fake broker, idempotence, reload, retention, missing cost fields, spoofing and TTL; renderer tests and isolated real-Electron smoke cover Board, Office, RPG, meetings and lounge. A real worker pilot, once authorized, should open a disposable Company profile, start an explicitly assigned permitted ChatGPT worker, refresh observations manually, inspect broker identity and review receipt, verify waiting/meeting/attention transitions, close app and reload to check continuity. No real profile or worker was touched in this task. Costs are displayed only when the company already has recorded nonzero usage; no per-worker hard limits or shell state are claimed.
